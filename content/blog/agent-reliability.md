去年底给一个内部系统接 Agent，演示很顺。第二次评审，业务方问了一句：这玩意儿连着跑一百次，能对几次？

我们答不上来。

后来补测：单次成功率 88%，连跑八次全对的概率不到 30%。那天下午讨论出来的东西，基本就是下面这些。

## 两个指标

评测里有 pass@k 和 pass^k 两个东西，名字像，意思相反。

pass@k 是给同一个任务 k 次机会、至少成功一次的概率，演示用的就是这个。pass^k 是连续 k 次全部成功的概率。用户不管你重试几次，他只问这次行不行。

单次 85% 的时候，八次全对是 27%。这个数不难算，但很少有人真的拿它去要求系统。

| 指标 | 回答什么 | 谁在用 | 容易出什么事 |
|---|---|---|---|
| pass@1 | 这一次成不成 | 论文、demo | 把长尾失败藏起来 |
| pass@k | 多试几次成不成 | 选型、汇报 | 高估可用性 |
| pass^k | 连跑 k 次是否都对 | 线上、SLA | 数字难看，但诚实 |

补测那天我们才发现，之前所有报告都是 pass@1。业务方看到的「88%」和我们心里的「88%」，根本不是一回事。

## 失败不是慢慢变多

一开始我以为可靠性是一条缓缓下滑的线，92% 加把劲到 95%。实际不是。

长任务里有一种现象叫熔断：模型跑到某一步突然开始绕圈，重复调同一个工具，或者把已经做完的子任务重新做一遍。公开数据里这个比例最高能到 19%，也就是五次长任务就有一次。

更别扭的是，能力强的模型熔断率可能更高。它更愿意一次规划五步、并行调三个工具，把自己推进一个更脆的状态。弱模型一步一停，反而容易被外部拦住。

我们内部也撞过一次：换了个更强的模型，单步指标涨了，线上事故反而多了。查了两天才想明白是这个问题。

## 有些动作不该让模型决定

聊可靠性很容易滑进「怎么把准确率从 92 提到 95」，但这个题目问错了。

先问另一个：失败了会怎样？

| 级别 | 例子 | 失败代价 | 做法 |
|---|---|---|---|
| 可重试 | 查库存、读订单 | 零 | 自动重试加退避 |
| 可回滚 | 改配置、建草稿 | 低 | 幂等键加快照 |
| 不可逆 | 退款、发邮件、删数据 | 高 | 人工确认 |

大部分事故不是模型在查库存上错了，是它在退款、发邮件上错了，而且没人拦。所以后来的第一优先级不是提准确率，是把不可逆动作从自动执行里摘出来。

这件事跟模型能力没关系，纯工程。

## 止损写在模型外面

试过在 prompt 里写「连续失败三次就停下来汇报」，基本没用。模型在循环里的时候恰恰最不清醒，它数不清自己失败了几次。

后来改成外部状态机，每一步都过一遍：

```python
async def guarded_run(task, budget):
    state = {"steps": 0, "cost": 0.0}

    while True:
        if state["steps"] >= budget.max_steps or state["cost"] >= budget.max_cost:
            return abort("budget")          # 超了就停，不商量

        step = await agent.next(state)

        if step.kind == "irreversible" and not step.confirmed:
            return escalate(step)            # 转人工是正常分支

        if step.kind == "done":
            return verify_and_commit(step)   # 完成与否由校验器决定

        state["steps"] += 1
        state["cost"] += step.cost
```

三个地方是关键：步数、token、金额，任何一项超了就中止；完成与否由外部校验器判断，跑测试、比 schema、看 diff，不是模型说完成就完成；转人工是一个正常分支。

最后一条听起来像废话，但很多系统把它当异常处理，日志里全是 error。实际上那经常是最正确的路径。

## 失败注入

补测之后我们往评测集里加了一组故意使坏的样本：工具延迟 30 秒、返回缺字段的 JSON、返回 ok 但内容为空、跑到一半换 schema、跑到一半把 token 撤了。

五类里最坑的是「假成功」。状态码 200、耗时正常、日志干净，只有后置断言能发现返回的是空。

这类样本的价值不在于抓 bug，而在于校准。加进去之后我们才知道，原来止损机制有一半根本没触发过。

## 最后

现在回头看，那次评审帮了我们。如果没人问「跑一百次能对几次」，我们大概还在拿 pass@1 的漂亮数字做汇报。

也不是说 pass^k 就是万能指标。它贵、慢，k 取多少本身也很主观。但至少它逼着你回答一个具体问题：失败一次，代价是什么。

这个问题答不上来，别的都是空谈。
